# Complete Spreadsheet Archive — Four-Anatomy Aortic FSI / Digital-Twin-Oriented Project

This package is the English-language spreadsheet archive for the four-anatomy aortic FSI surrogate-modeling project. It preserves the original numeric CSV data exactly as used by the analysis pipeline and provides a fully English catalog, manifest, column dictionary, pipeline map, superseded-file register, and file-by-file guide.

## Package contents

- **99 original project CSV files** organized into nine stage-based folders.
- **DigitalTwin_Spreadsheet_Catalog_EN.xlsx** — the main Excel catalog with dashboard, complete file catalog, pipeline map, key-column dictionary, and superseded-file register.
- **MANIFEST_ALL_SPREADSHEETS.csv** — machine-readable catalog for all 99 included spreadsheets.
- **FILE_BY_FILE_GUIDE.md** — detailed English description of every included spreadsheet.
- **PIPELINE_MAP.csv** — compact stage-by-stage data-flow map.
- **KEY_COLUMN_DICTIONARY.csv** — definitions, units, and interpretation notes for the most important columns and naming patterns.
- **EXCLUDED_SUPERSEDED_FILES.csv** — files intentionally excluded from the canonical archive and the reason for each exclusion.
- **SHA256SUMS.txt** — integrity hashes for all package files other than the checksum file itself.
- **spreadsheets_original_csv/** — unchanged copies of the original CSV data files, grouped by pipeline stage.

## Why the project files are stored as CSV rather than converted to .xlsx

Most project tables were generated by COMSOL/Python workflows as CSV files. CSV is directly readable by Microsoft Excel while preserving a simple, transparent, versionable representation for numerical pipelines. To avoid changing floating-point precision, delimiters, encoding behavior, or downstream reproducibility, the original data CSVs are included **without numeric transformation or spreadsheet conversion**. The separate Excel catalog is provided for navigation and documentation.

## Scientific scope and terminology

The package corresponds to four independent computational aortic anatomies (A1–A4). The thousands of surface nodes in the CSV files are spatial samples within these four anatomies and must not be interpreted as thousands of independent patients. A1–A3 form the development cohort for the geometry-only prior; A4 is the separate target-excluded zero-shot anatomy in the original evaluation hierarchy. Sparse A4 calibration analyses are post-zero-shot secondary field-completion analyses.

The current project is best interpreted as a computational surrogate/update component relevant to future cardiovascular digital-twin development. It is not a validated clinical digital twin, and the sparse A4 anchor values are FSI-derived oracle labels rather than clinical sensor measurements.

## Directory structure

### 01_Core_FSI_Processed — 8 files
Canonical processed hemodynamic and wall-mechanical tables for A1–A4. These are the primary FSI target sources for downstream machine-learning and diagnostic analyses.

### 02_FSI_Raw_and_Audits — 22 files
Raw time-series exports and verification/audit tables used to construct or validate the canonical FSI target fields. These include native-versus-reconstructed WSS comparisons and timewise VM/WSS summaries.

### 03_DigitalTwin_V1 — 7 files
Geometry-only cross-anatomy prior stage: A1–A3 training table, A4 geometry-only feature table, LightGBM candidate evaluation, selected models, out-of-fold predictions, and historical A4 zero-shot outputs.

### 04_DigitalTwin_V2 — 4 files
Sparse-personalization stage: development LOAO personalization results, calibration summaries, A4 personalized metrics, and pointwise A4 personalized predictions.

### 05_DigitalTwin_V3 — 18 files
Diagnostic extension containing empirical residual-band data, geometry-support/OOD analyses, anchor masks, Pareto/co-burden tables, uncertainty summaries, figure metadata, and the V3 master pointwise table.

### 06_Final_4Anatomy_Consolidated — 11 files
Consolidated final-analysis outputs combining development candidate selection, OOF predictions, sparse personalization, A4 zero-shot results, A4 personalized results, and selected sensitivity tables.

### 07_Sensitivity_Ablations — 15 files
Sensitivity analyses that alter the development-anatomy composition or remove/retain selected components. These tables test whether the main conclusions depend strongly on one development anatomy or a specific personalization component.

### 08_Reviewer_Controls — 5 files
Reviewer-motivated same-anchor controls and robustness tables: development-only KNN/IDW/RBF hyperparameter selection, A4 tuned baseline performance, pointwise baseline predictions, nearest-anchor-distance sensitivity, and computational timing context.

### 09_Paper_Tables — 9 files
Compact main-text and supplementary tables derived from the analysis outputs for manuscript reporting.

## Important version-control notes

- `Patient4_CycleResolved_SolidMechanics_v2.csv` is the valid/canonical A4 mechanics table. The older non-v2 file is superseded and is not included in the canonical data folders.
- `Patient4_VM_Raw_TimeSeries(1).csv` is the corrected A4 raw VM time-series export used by the valid audit chain.
- Historical V1 outputs generated with the hard-coded 450-tree final refit are preserved for reproducibility. In manuscript V10, the corrected candidate-specific selected-tree-count analysis is the primary interpretation; historical 450-tree results are sensitivity/audit material only.
- Scratch files such as `test*.csv` and `dt_*_tmp.csv` are intentionally excluded.

## Data integrity

The original CSV data files under `spreadsheets_original_csv/` were copied without changing their numeric content. The manifest records SHA-256 values for the included project spreadsheets, and `SHA256SUMS.txt` provides package-level integrity hashes.

## How to use the Excel catalog

Open `DigitalTwin_Spreadsheet_Catalog_EN.xlsx`:

- **Dashboard** — package-level counts, category sizes, and a quick navigation guide.
- **File_Catalog** — one row per included spreadsheet, with stage, status, scope, dimensions, producer, downstream use, key columns, description, notes, paths, and SHA-256.
- **Pipeline_Map** — the complete tabular data flow from geometry/FSI generation through V1/V2/V3, reviewer controls, and paper-ready summaries.
- **Key_Columns** — English definitions and units for the major FSI, geometry-feature, model-metric, anchor, OOD, uncertainty, and Pareto columns.
- **Excluded_Superseded** — files that should not be treated as canonical inputs and why.

## Source geometry note

The source vascular geometries were obtained from the Vascular Model Repository: https://www.vascularmodel.com/dataset.html. Geometry preparation in the study followed the documented VTP → ParaView/STL → CATIA wall/lumen STEP → COMSOL workflow before tabular FSI outputs were exported and processed.
